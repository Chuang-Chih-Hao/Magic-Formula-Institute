# 🧪 魔法配方研究所｜魔法小鎮開店日

適合**國小六年級**的多人即時數學經營遊戲，以「比、比值、等比、比例式、生活比例」為核心。學生經營自己的可愛魔法飲料店，透過解題解鎖配方、調整三種材料的比例、決定售價，接待會自行評估商品是否值得購買的動物 NPC。最後比較每間店的**淨利**，而不是只看售價。

> 正式課堂預設四位學生各自使用一台裝置，另外由老師在自己的畫面開房與控制。**不必滿四人**；只要有一位學生，老師就能開始。

## 🎮 遊戲玩法

1. **老師開設魔法教室**：首頁選「建立新的魔法教室」，取得六位數房間代碼；教師不計入四個學生名額。
2. **學生進入**：在自己的裝置開同一網址，輸入代碼與暱稱。先幫自己的小店命名，選草莓、紫藤、森林或蜜桃裝潢。
3. **老師開始營業**：可選 20、25、30、35 或 40 分鐘。學生可以開始玩；老師可隨時暫停、繼續或提前結算。
4. **挑戰比例題，解鎖配方**：點擊鎖住的配方卡，完成一道題目。答對可取得配方與 24 金幣；答錯不倒扣，會給出正確答案與解法，鼓勵再試。也有 +18 金幣的加碼練習。
5. **按比例調飲**：例如配方花露：星糖：月光水為 **2：1：1**，可輸入 2、1、1，也可等倍放大為 4、2、2。等比越精準，品質越高。每次調製一鍋 3 杯，從持有金幣扣除材料成本。
6. **自由實驗**：不解題也能隨機調配「神秘特調」，但隱藏配方不固定、品質有額外不穩定性，可能不受歡迎。
7. **裝飾魔法小店**：累積金幣後可以購買「迎賓花圃」「星光燈串」「甜點座位」，裝飾會出現在自己的 2D 店鋪場景，也會增加顧客的購買意願。裝修費同樣列入經營成本。
8. **自己訂價**：每杯可賣 10～80 金幣，展示架商品可用 +／− 5 金幣快速調價。客人約每 11 秒來一次，會考慮自身預算、喜好的口味、商品品質和售價，決定是否購買。沒有庫存就不會成交。
9. **查看排行榜**：淨利 = 營收 − 製作成本。遊戲結束依淨利排名，鼓勵學生比較「等比正確」和「價格策略」如何影響結果。

六種飲品：🍓 莓果初戀、🌙 月光蘇打、🌿 森林薄荷、🍑 蜜桃星星、🫐 紫晶夢境、🌈 彩虹晨露。

## 📚 建議 40 分鐘教學流程

| 時間 | 教師與學生任務 |
|---|---|
| 0–5 分 | 教師開教室、學生加入與自訂店名，示範淨利概念 |
| 5–12 分 | 解鎖一張配方，辨認三項比與等比擴大 |
| 12–30 分 | 經營競賽：調飲、訂價、觀察 NPC 購買、修正比例策略 |
| 30–35 分 | 教師提前結算，公布淨利排行榜 |
| 35–40 分 | 回饋：為什麼高品質不一定賣得好？改價和更改比有什麼差別？ |

可將遊戲時間設為 **25～30 分鐘**，依班級進度調整。遊戲中的「品質分數」是一種把三項比例與顧客喜好轉成模擬結果的機制，不代表真實飲料的科學測量。

## 🤖 NPC 與可選的 AI

- **無需任何 API Key** 即可玩完整遊戲。NPC 使用伺服器端的購買判斷演算法，參考預算、偏好、品質、價格及機率；每次是否購買並非由前端決定，因此學生不能直接竄改分數。
- 可選擇以 OpenAI API **生成少量個性化顧客台詞**：在 Render 服務環境變數設定 AI_NPC_ENABLED=true 和 OPENAI_API_KEY，必要時設定 OPENAI_MODEL（預設 gpt-4o-mini）。為避免意外費用，每一間教室最多約每 45 秒產生一次 AI 台詞；API 失效時自動使用原本的台詞。
- **AI 只補充顧客台詞，不負責判定是否購買或修改成績**。請勿把 API Key 放入網頁或 GitHub。AI 請求只包含虛構 NPC、商品與交易情境，不包含學生姓名。

## 🧰 技術結構

- server.js：Node.js + Express + Socket.IO，多人房間、數學題庫、權威伺服器計分、NPC 定時顧客與可選 AI。
- public/index.html、style.css、app.js：無須前端建置的 2D 可愛風網頁遊戲，以 CSS 繪製場景和飲品。
- test/game.test.js、test/rooms.test.js：數學題、比例品質、購買傾向、單人／四人 Socket.IO 連線流程測試。
- render.yaml：Render Web Service Blueprint 設定。
- .github/workflows/ci.yml：每次推送執行測試。

需求：Node.js 20 或更新版。

在本機啟動：

    npm install
    npm test
    npm start

開啟 http://localhost:3000 。健康檢查：http://localhost:3000/health 。

## 🚀 Render 部署（由教師自行建立）

這個專案需要 WebSocket 伺服器，所以**必須選 Web Service，不是 Static Site**。可使用 Render Blueprint 自動讀取根目錄 render.yaml，也可以自行建立：

1. 登入 [Render](https://dashboard.render.com/)，選 **New → Web Service**。
2. 連結 GitHub 儲存庫 [Chuang-Chih-Hao/Magic-Formula-Institute](https://github.com/Chuang-Chih-Hao/Magic-Formula-Institute)，選 main 分支。
3. 選擇 **Language/Runtime：Node**，**Build Command：npm install**，**Start Command：npm start**。Root Directory 留白。
4. 方案可先選 **Free**；Health Check Path 設為 **/health**，Auto-Deploy 選 On Commit。
5. 按 **Create Web Service**。等 Render 顯示部署成功後，會產生一個 https://xxx.onrender.com 網址，學生和教師皆使用此網址。
6. 開啟網址應看到「魔法小鎮開店日」首頁；https://xxx.onrender.com/health 應回傳類似 {"ok":true,"activeRooms":0} 。再用教師視窗開房，及另一個視窗或手機測試加入和開始遊戲。

**重要限制**：本版教室、配方和成績放在單一 Node 服務的記憶體中，**伺服器重新啟動、休眠後被重新啟動或重新部署時，房間與進度會消失**。同一場課程請避免中途部署，並建議使用單一執行個體。Render Free 方案可能休眠與冷啟動，請上課前提前開啟網站確認可用。學生裝置重新連線時，若伺服器未重啟，系統會用瀏覽器儲存的識別碼恢復原店鋪。

### 完成 Render 建立後的檢查

將你的 **Render 網址** 回傳至這個對話，即可再做公開網址、健康檢查、實際 WebSocket 連線、教室加入、出題與 NPC 交易等驗收；目前還未替你建立 Render 服務。

## 🔒 隱私與安全

- 使用遊戲暱稱即可，無需提供學生的真實姓名或帳號。
- 房主身分採隨機秘密識別，學生身分以隨機 token 恢復，皆保留在各自的瀏覽器中，不應分享。
- 單一房間最多四名學生，教師為管理者不佔名額。
- 本版不含持久化資料庫、帳號系統或防止有心人士多開裝置的嚴格身分驗證，適合教師監督的課堂使用，不適合有現金價值的競賽。
