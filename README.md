# 🎪 魔法配方研究所 2.0｜動物小鎮園遊會

**國小六年級的「比、比值與比例應用」多人 2D 經營教學遊戲。** 四位（或更少）學生各自設計一間可愛攤位，先選三款飲品、調配材料、訂價、搭配裝飾，確認後永久鎖定該場設定。老師宣布開市後，所有攤位都出現在同一張 2D 園遊會地圖，NPC 動物步行比較所有攤位並決定在哪間買，最後以淨利排名。

- 🌷 [直接開玩](https://magic-formula-institute.onrender.com)
- 🛠️ [Render 控制台](https://dashboard.render.com/web/srv-dbu40qtckfvc73b1m58g)
- 📦 [GitHub 程式庫](https://github.com/Chuang-Chih-Hao/Magic-Formula-Institute)

## 一、準備期：先打造並鎖定攤位

1. 老師開教室，取得六位數房號；教師不佔學生名額，最多四位學生。
2. 學生輸入暱稱、取店名，選擇明顯不同的 2D 建築：🍓 草莓糖果屋、🔮 紫晶星光塔、🌿 森林玻璃屋、🍑 蜜桃茶亭。外型不只是換色。
3. 選擇兩件裝飾，每件在地圖有實際的物件、動畫與可量化的 NPC 加成。
4. 選好三款**不同**飲料。初始解鎖莓果初戀、月光蘇打、森林薄荷。完成比值與比例題可取得蜜桃星星、紫晶夢境、彩虹晨露。
5. 每杯設定花露、星糖、月光水（各 1–12 匙、總數不超過 27 匙）與售價 12–80 金幣。比例與配方相同或等倍放大時品質為 100 分，例如 2：1：1 與 4：2：2 品質相同。食材用量影響每杯成本。
6. 點「🔐 三款飲品確認，鎖定攤位」。系統會**自動儲存所有設定**，然後鎖定。該場不能更改建築、裝飾、材料、飲料種類或價格。
7. 老師在所有學生準備好後按「🎉 全員就緒，宣布開市」。即使只有兩位學生也能開市。

## 二、營業期：2D 地圖上的 NPC 自由比價

- 所有學生與老師都會看到同一個手繪 Canvas 2D 魔法園遊會：四角攤位、中央噴泉、石板路、樹木、裝飾及走動的小動物。
- NPC 從入口走進來，途中可走訪不同攤位，最後到最有吸引力的攤位決定買不買。所有玩家共用同一個顧客池，不再各店分開隨機出現 NPC。
- 購物比較考慮**品質、價格與顧客預算、喜好的甜美／清爽／夢幻口味、攤位裝飾**，加入少量偏好差異。超出預算不列入選購；即使分數最高也可能放棄購買。
- 點地圖上的動物可追蹤其路線與各攤位比較分數；點攤位可看三款飲品品質、價格與裝飾。
- 右方「顧客園遊會日記」會顯示到哪間購買及主要原因，Gemini 台詞也會留在日記。
- 開市後所有設定鎖定。每賣出一杯，收入增加一杯售價，同時將每杯材料成本列入成本；**淨利＝營收−成本**。
- 老師可選營業 10、15、20、25 或 30 分鐘，暫停、繼續或提前結算。

## 三、裝飾不再只是換顏色

| 可見裝飾 | 地圖中的物件與動態 | NPC 評分加成 |
|---|---|---|
| 🎡 巨型風車招牌 | 旋轉的粉色風車與招牌 | 所有口味 +16 分 |
| 🌷 蜜糖花圃 | 攤位旁盛開的大型花圃 | 喜歡甜美 +25 分 |
| ⛲ 薄荷水泉 | 水池、噴泉與水花 | 喜歡清爽 +25 分 |
| ⭐ 星光小舞台 | 星星舞台與閃亮光點 | 喜歡夢幻 +25 分 |
| 🥤 試飲小桌 | 店前木桌與試喝飲料 | 所有口味 +12 分 |

每位學生只能選兩項。配合三杯飲品的口味決定佈置會更有策略；強勢裝潢不保證成交，價格與品質同樣關鍵。

## 四、題目變化

新題庫包含**14 種題型結構**：化簡比、比值、等比擴大、比例式、按比例分配、等比定價、三項比例、比的比較、總量分配、倍數推算、未知後項、比值辨識、園遊會優惠與比例推理。每題隨機替換情境、原料、數字、單位及敘述，並保留近期出題歷史，降低重複頻率，避免連續出相同結構。答錯會顯示正解與解析；答對可取得研究星星，並依題目解鎖新飲品。

## 五、Gemini NPC AI

遊戲可完全離線於 AI 服務運作，NPC 購買選擇只由伺服器規則決定。已可選用 **Gemini 3.5 Flash-Lite** 產生繁體中文顧客台詞。

Render 的 Environment 需安全設定 GEMINI_API_KEY、AI_NPC_ENABLED=true（可選 GEMINI_MODEL）。金鑰只留在伺服器，**不要寫進 GitHub、網頁或對話**。只傳虛構 NPC 的購買情境，不傳學生姓名或答題資料。每房間至多約每 45 秒要求一次 AI 台詞，失敗或用量限制時自動使用遊戲內建台詞，數學、交易與排名不受影響。

公開的 https://magic-formula-institute.onrender.com/health 可查看 game、ok 與 npcAiMode，但辨識金鑰不等於每次 AI 呼叫都成功。

## 六、建議上課安排（40＋10＋40 分鐘）

| 時間 | 活動 |
|---|---|
| 第一節 0–5 分 | 老師開房、學生加入 |

| 休息 10 分 | 保留房間，不要重新部署 |

| 25–40 分 | 營業結算、分析品質與價格／裝潢對選擇的影響 |

## 七、程式架構與測試

- fair-server.js：新遊戲的權威伺服器，負責房間、準備／鎖定／營業狀態與跨店購買。
- fair-questions.js：14 類比例變化題與近期題目避重。
- public/fair.js、fair.css、index.html：Canvas 2D 動畫場景、互動攤位、NPC 地圖與 UI。
- server.js：提供已完成的 Gemini 對話輔助功能；原有 public/app.js、style.css 為停用的舊版介面。
- test/fair-v2.test.js：四人房間、不可改動鎖定商品、相互比較顧客、裝飾與題庫測試。
- test/gemini.test.js：Gemini 呼叫、備援與節流測試。
- test/browser-smoke.js：教師與學生在真正 Chromium 瀏覽器裡準備、鎖定、開市、查看動物交易。
- GitHub Actions：自動化語法與單元整合測試，另提供瀏覽器測試工作流程。

本機執行（Node.js 20 以上）：

    npm install
    npm test
    npm start

瀏覽器開啟 http://localhost:3000。Render 仍使用原本 Web Service：Build Command 為 npm install --omit=optional，Start Command 為 npm start，健康檢查路徑 /health。

**重要：** Render Free 可能休眠；遊戲房間和分數目前儲存在單一伺服器記憶體中。休眠後重啟、重新部署或伺服器意外重啟會清除正在進行的房間。正式上課前先檢查網站，課堂中避免部署。

本作為教學遊戲，NPC 評分是可解釋的簡化模型，並非現實商業顧客的預測。2D 場景以原創 Canvas 繪圖呈現，無須購買素材或遊戲引擎。
